# APP 产线执行指南

本 Skill 属于 APP v0.1.0 的初版规范；不代表已安装自动化调度器或获准生产发布。

## 先读后做

相对路径以本 Skill 所在目录为基准：

1. [产线入口](<../../../lines/app/README.md>)。
2. [10 节点](<../../../lines/app/pipeline.md>) 与 [质量门禁](<../../../lines/app/quality-gates.md>)。
3. [DSH 操作指南](<../../../lines/app/dsh-playbook.md>)。
4. 用户指定的项目运行档案和产品仓库状态；没有档案时使用 [模板](<../../../templates/project-run.md>)，先征询缺失信息。

确认产线版本与工厂 Git SHA；不把工作区的最新规则悄悄替换项目锁定的版本。Skill 正文可随文件修改变化，因此可复现项目应使用固定快照或记录内容版本。

## 执行

- 从项目实际节点开始，而非每次机械地回到立项；缺少准入证据时先补齐。
- 先做一个端到端功能切片。按 [任务模板](<../../../templates/task.md>) 明确输入、依赖、接口、文件边界、预算与验收。
- 小任务直接执行；独立任务可委派子 Agent，但不允许冲突写入。只有用户明确要求工作流或大规模多 Agent 编排时才使用 Workflow 工具。
- 对需要长期推进的任务使用受授权的 Goal；Goal 不替代产品状态台账、人工批准或外部作业持久化。
- 实现后独立审查、执行实际验证，提供命令、环境、退出码、产品提交、制品摘要及报告。
- G1–G5 使用 [门禁模板](<../../../templates/gate-review.md>)；当前版本均由人批准。不得杜撰验收或把尚未验证标为通过。
- 生产发布、破坏性迁移、付费资源和权限变更必须具备明确授权；开发授权不自动包含这些操作。

## 复盘与改进

记录阻碍、返工和验证成本，生成 [候选经验](<../../../templates/lesson.md>) 或 [改进提案](<../../../templates/improvement.md>)。产品修复与工厂升级分开；没有明确修改工厂的授权时只提出候选。遵循 [改进闭环](<../../../factory/improvement-loop.md>)，不自行降低验收要求或改评测结果。

## 输出

报告当前节点、实际完成范围、证据、未决问题、需要用户决定的事项以及下一步。仓库结构校验通过不代表 APP 测试通过，测试通过不代表用户已批准上线。
