# APP 产线 v0.1.1

状态：可用于首个项目试运行的规范基线，尚未经过真实 APP 项目验证。不是全自动软件生成器。

## 适用范围

默认面向带客户端、后端和数据存储的手机 APP。Web、桌面 APP 可复用主体流程，但必须在项目运行档案调整平台测试和发布要求；不适用项需要理由。游戏暂不属于本产线，见 [游戏占位](<../game/README.md>)。

## 一条产线的最小闭环

```text
APP-01 立项 → APP-02 需求 [G1] → APP-03 设计 → APP-04 技术风险 [G2]
    → APP-05 工程准备 → APP-06 增量开发 ↔ APP-07 集成验证 [G3]
    → APP-08 业务验收 [G4] → APP-09 发布 → APP-10 观察复盘 [G5]
                                             ↘ 候选工厂改进
```

这不是严格瀑布：每个功能切片可循环经过需求、设计、开发和验证；发现重大假设失效要回退。批准基线后发生范围变化须重新评估受影响门禁，而不是每个小修改都重做全部文档。

## 首个 APP 启动步骤

1. 明确产品仓库路径、目标平台、用户、核心场景、预算和部署权限；本工厂仓库不承载产品源码。
2. 将 [项目运行档案](<../../templates/project-run.md>) 复制到产品仓库的项目文档区，记录 APP 版本 `0.1.1` 和实际工厂 Git 提交 SHA；不要只记录可移动的 `main`。
3. 填写 MVP 和非目标，列出需求 ID、验收方式、非功能指标、未决问题，推进 APP-01/02 后请求 G1。
4. 阅读 [流程节点](<pipeline.md>)、[质量门禁](<quality-gates.md>) 和 [DSH 操作指南](<dsh-playbook.md>)，按依赖拆分 [任务包](<../../templates/task.md>)。
5. 先交付一个完整用户路径，再扩展功能。实现、审查、验收及发布分别留证据。
6. 每个关键里程碑记录阻碍和人工介入，并更新[试运行验证清单](<../../factory/first-project-trial.md>)；流程问题按 [改进闭环](<../../factory/improvement-loop.md>) 提案，避免边开发边无痕改变规则。

## 产物位置

- 产品需求、设计、代码、测试、发布、批准：产品仓库/受控制品存储。
- 工厂流程、通用模板、Skill：本仓库。
- 脱敏的项目索引与经验：本仓库的 [projects](<../../projects/README.md>)、[00-Inbox](<../../00-Inbox/README.md>) 和 [improvements](<../../improvements/README.md>)。
- 大文件、签名密钥、生产数据不放到本仓库；报告可以引用受控存储并记录摘要及访问约束。

## 如何知道完成

必须同时满足需求验收、工程 DoD、所需门禁批准以及实际交付要求。阶段完成不能冒充整个 APP 上线。测试失败、证据缺失、预算耗尽、等待用户批准分别报告，不能统一写“完成”。
