# DSH 中执行 APP 产线

## 第一次使用

1. 在 DSH 选择产品仓库作为开发工作目录；确定对产品代码和工厂知识库各自的访问权限。
2. 指向工厂的 [APP 入口](<README.md>)，明确要求按本产线执行，并提供产品运行档案。先读本档案和当前 Git 状态，不在工厂目录生成产品源码。
3. 在工厂仓库会话中，`.dsh/skills/app-production-line/` 可由启用的本地 Skills 提供方发现。另一个 Git 产品仓库不会自动继承该 Skill：第一版可显式读取其绝对路径；后续在授权后通过 DSH 的共享 Skill 目录或 customSkillDirs 发布。
4. 若权限不允许读取工厂目录，使用经批准的版本快照到产品工作区，保留来源 SHA；不要用更换目录绕过权限。
5. 记录本次使用的工厂 SHA、产线版本和 Skill 内容版本。仓库里有 Skill 不等于已在每个会话加载成功。

## 可复制的启动提示

```text
我要开发一个 APP。请使用我指定的工厂知识库中的 APP 产线。
先读取 APP 入口、流程、质量门禁和项目运行档案。
当前产品仓库：[填写路径]
工厂仓库或只读快照：[填写路径与提交 SHA]
目标用户与核心问题：[填写]
目标平台和预算：[填写]
当前授权：分析、项目工作区内开发和验证；生产发布另行批准。
从 APP-01 开始，列出缺失信息和最小功能切片，不直接跳到编码。
关键门禁请提供证据与待批准结论。遇到流程问题形成改进提案，
不要自行修改共享规则、降低验收标准或增加权限。
```

以上是模板，不是已经获得的权限；实际用户请求和系统策略始终优先。

## DSH 能力如何使用

| 能力 | 本产线中的作用 | 边界 |
|---|---|---|
| Goal | 在用户授权的长任务中持续推进明确目标 | 不等于 durable CI 队列；不自动批准发布 |
| 子 Agent | 有界地分派独立实现、测试、审查 | 先分文件/工作树；上下文独立不等于文件隔离 |
| Skills | 按需加载流程和知识检索规则 | 不将全文资料塞进每轮提示；内容应固定版本 |
| Workflow | 经用户明确要求时进行较大规模编排 | 小任务用普通委派；JSON 节点索引不会自行运行 |
| 文件/Git/测试工具 | 读取知识、执行验证、生成证据 | 测试通过必须来自真实结果；不要只相信摘要 |
| 扩展/MCP | 未来需要时接入知识或发布服务 | 本版未安装，也不依赖它们 |

## 每个任务的交接

给实现者：需求/任务 ID、当前节点、输入版本、接口、写入范围、测试与验收、预算和不可执行操作。

要求返回：变更摘要、提交/差异、执行命令及结果、证据路径、未决事项、候选经验。给审查者同一需求和实际 diff，不预先要求忽略问题。

协调者核验最终合并状态，更新 [任务包](<../../templates/task.md>)，按 [门禁记录](<../../templates/gate-review.md>) 请求放行。角色拆分不是所有任务都要多个模型；简单修改可单 Agent 实现再做独立验证。

## 恢复与知识沉淀

恢复先核对运行档案、分支、HEAD、未提交变更和已有测试，禁止覆盖用户未提交内容。非幂等外部操作先确认是否已经执行。

查询知识时按项目、技术栈、版本、状态筛选，再读取原文。使用旧知识前验证适用性。产品文档中的真实敏感内容不自动复制到工厂仓库。任务完成后提出候选经验/改进，正式晋级依照 [改进规则](<../../factory/improvement-loop.md>)。

## 验证本接入

在以工厂目录为工作目录的新会话中，确认 Skill 可发现、能读取 APP 流程、能指出缺失准入条件；在产品会话中验证显式引用路径和权限。首次真实项目记录这些结果。当前仓库文档校验通过不能冒充此会话级验证已经完成。
